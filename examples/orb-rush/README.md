# Orb Rush

A complete, publishable 3D arcade game made with Zvibe Editor, built entirely through the editor's MCP tools: level geometry, materials, lighting and shadows, Havok physics, sounds, scripts, camera, post-processing, and the web release build.

Roll the orb around a neon arena, knock over crate pyramids, dodge the spinning sweeper, climb the pillars, and collect all 12 gems before the timer runs out.

## Controls

| Action      | Keyboard              | Touch                                 |
| ----------- | --------------------- | ------------------------------------- |
| Roll        | WASD or arrow keys    | Drag on the left half of the screen   |
| Jump        | Space                 | Tap on the right half of the screen   |
| Look around | Mouse drag, or Q / E  | Drag on the right half of the screen  |
| Start / restart | Enter, or click/tap | Tap                                  |
| Restart run | R                     |                                       |

Falling off the arena costs 5 seconds. Your best time is saved in the browser.

## What's inside

- **Physics (Havok):** a dynamic orb driven by forces, 20 dynamic crates in two pyramids, a kinematic spinning hazard, and static walls, plateau, ramps and pillars.
- **Audio:** looping music plus pickup, jump, impact, crate-impact (3D positional), hazard, countdown tick, start, win and lose sound effects. Every sound is original and generated by `tools/generate-audio.mjs` (CC0).
- **Scripts** (`src/scripts`): `player-controller.ts`, `follow-camera.ts`, `spinner.ts`, and a scene-level `game-manager.ts` that owns the rules, HUD (Babylon GUI), particles and sound playback. They share state through `src/game/state.ts`.
- **Rendering:** PBR and grid materials, a shadow-casting sun with PCF shadows, image-based lighting, and a default rendering pipeline with bloom, ACES tone mapping, vignette and FXAA.

## Develop

This example lives inside the Zvibe Editor repository and uses the repository's own runtime (`babylonjs-editor-tools`) and CLI through `file:` dependencies, so build them first from the repository root (`yarn build-tools && yarn build-cli`).

```bash
yarn install
yarn dev          # http://localhost:3000
```

`public/scene` is the editor's export of `assets/example.scene`, committed so the game runs without opening the editor. Re-export it from Zvibe Editor after changing the level.

Open `project.bjseditor` in Zvibe Editor to edit the level. Scripts' exported values (speeds, time limit, camera distance, …) are editable in the Inspector.

## Publish

In Zvibe Editor, use the **Web Release** build profile (**Build**), or run the MCP tool `build_build_profile` with `id: "web-release"`. The build exports the scene into `public/scene` and runs `vite build` into `dist/`.

`dist/` is a static site that works from any sub-path, so you can upload it as-is to itch.io (zip the folder, "HTML" project), GitHub Pages, Netlify, or any static host. Serve `.wasm` files as `application/wasm` (all mainstream hosts do).

## How it was made

`tools/author-orb-rush.mjs` is the exact MCP session that built the game in a running Zvibe Editor (about 140 tool calls: `create_primitive_mesh`, `create_instance`, `create_material`, `set_mesh_physics`, `set_light_shadows`, `create_sound`, `write_script`, `attach_script`, `set_camera_post_process`, `create_build_profile`, `build_build_profile`, …). Run it against an editor with this project open:

```bash
BABYLONJS_EDITOR_MCP_PORT=3712 node tools/author-orb-rush.mjs ../../mcp/server/index.mjs .
```

## Test

`yarn playtest` serves `dist/` and plays the production build in headless Chromium with real keyboard input. It checks loading, physics, sounds and music, rolling, jumping, crate collisions, gem collection, winning, restarting, and that there are no runtime errors or failed requests (install a browser once with `npx playwright install chromium`).

Regenerate the sounds with `yarn audio` (`tools/generate-audio.mjs`).
