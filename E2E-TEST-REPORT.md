# Zvibe Editor end-to-end test report

This report covers an end-to-end pass over the whole editor. It lists every feature, verifies the MCP server against a running editor, checks the free-asset marketplaces, and builds a complete game (physics, sound, scripts, UI and a web release build). Everything was driven through the editor's own MCP tools.

Environment: Linux container (4 vCPU) with Electron under `xvfb-run` and software WebGL (SwiftShader). Outbound network is restricted by policy. Because of this, the timings here are several times slower than on a desktop with a GPU. It is also why a few scenarios are marked as blocked by this environment.

## Complete game: Orb Rush

`examples/orb-rush` is a complete, publishable 3D arcade game. It was authored end to end through MCP by `tools/author-orb-rush.mjs`, which makes about 140 tool calls covering level geometry, materials, lights and shadows, Havok physics bodies, sounds, scripts, camera, post-processing and the web build.

- **Physics (Havok):** a force-driven player orb, 20 dynamic crates in two pyramids, a kinematic spinning sweeper, and static walls, ramps, pillars and a plateau. Forces are applied once per physics step, with fixed 1/60 s sub-steps so stacks stay stable.
- **Sound:** looping music plus pickup, jump, impact, 3D-positional crate impact, hazard, countdown, start, win and lose effects. All are original and generated by `tools/generate-audio.mjs` (CC0).
- **Gameplay:** 12 gems, a timer, a fall penalty, best time saved in the browser, a HUD built with Babylon GUI, keyboard and touch controls, and restart.
- **Publishing:** `yarn build` produces a static site with relative paths, so it can be hosted on itch.io, GitHub Pages or any static host. It can also be packaged with the Electron template.
- **Play-test** (`yarn playtest`, Playwright against the production build), 18/18 checks: the scene loads, Havok runs with all 20 crate bodies, all 10 sounds load, music starts on the first gesture, the orb rolls and jumps under physics, crates get knocked over, the sweeper spins, the camera stays inside the arena, collecting every gem wins, restart resets gems and crates, and there are no runtime errors and no failed requests.

Building it exposed real engine-integration bugs that affected every exported game. They are now fixed in the runtime and all five project templates:

| Bug                                                                                                                          | Fix                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| No sound in exported games: templates never created a Babylon Audio V2 engine                                                | Templates call `CreateAudioEngineAsync()` (602850e)                                                    |
| Everything fell in slow motion: Havok's default 200 units/s velocity cap assumes meters, but the editor works in centimeters | Velocity limits raised to 20000 cm/s in the editor and all templates, with a regression test (602850e) |
| Games crashed with "No values found for script" when a script had no exported values                                         | Decorators keep their field defaults (602850e)                                                         |
| `create_primitive_mesh` ignored its size/segment options                                                                     | Options are applied and validated (7d44090)                                                            |
| Agents could not attach a script to the scene (game-manager style)                                                           | Scene-level script owners (54fedf3)                                                                    |
| The web build planned to strip modules that the runtime loader needs                                                         | The planner scans the runtime and keeps them (af49d21, cc291ef)                                        |

## Free-asset marketplaces

The editor ships Poly Haven and ambientCG providers (no API keys needed), plus a Sketchfab provider. This container's network policy rejects connections to their hosts, and Electron's own network stack cannot reach external hosts here at all (even `registry.npmjs.org` fails from the editor while `curl` succeeds). So live search and download could not run here. Instead:

- **Offline tests (17, `editor/test/tools/marketplaces/providers.test.mts`)** cover search parsing, download-option selection (glTF/GLB/texture sets preferred over `.blend`/`.fbx`, case-insensitive resolution matching, HDR/EXR as environments), and file-path safety.
- **Security hardening (bf16db2):** downloads can no longer write outside the asset directory (`../` or absolute paths coming from provider metadata), asset IDs and file names are sanitized, the MD5 checksums that providers publish are verified before writing, and HTTP errors are reported instead of being parsed as JSON.

To exercise the marketplaces live, allow these hosts in the environment's network settings: `api.polyhaven.com`, `dl.polyhaven.org`, `cdn.polyhaven.com`, `ambientcg.com`, `api.sketchfab.com` and `cdn.babylonjs.com`. Then run `node mcp/scripts/marketplace-live-scenario.mjs` against a running editor.

## Reproducing

```bash
yarn install && yarn build
yarn test                                               # tools + editor unit tests
yarn workspace babylonjs-editor-mcp-server validate    # MCP contract
yarn start                                              # open a project, then in another shell:
node mcp/scripts/<name>-live-scenario.mjs               # any live scenario (needs the running editor)
cd examples/orb-rush && yarn install && yarn build && yarn playtest
```
