# Unity 6.5 Parity Matrix

This is the implementation contract for Unity-class editor parity. It is based on the Unity 6/6.5 feature families documented by Unity, not a claim that Babylon.js can reproduce every Unity runtime or platform feature. A row is **Complete** only when the editor UI/model, save/load/export path, MCP tool surface, and a live MCP scenario have all been verified.

Unity’s Unity 6 documentation identifies dedicated ProBuilder, Shader Graph, VFX Graph, terrain/world-building, physics, rendering, profiling, and package workflows. Unity 6.5 is a supported Unity 6 release. [Unity 6.5 release](https://unity.com/releases/editor/whats-new/6000.5.3f1), [Unity 6 feature documentation](https://docs.unity3d.com/6000.1/Documentation/Manual/WhatsNewUnity6Preview.html).

## Latest verified parity increments

- **Model LOD authoring:** Generated model LODs process static, skinned, morph-target, and combined skinned/morph meshes with exact source-vertex provenance, reconstructed vertex/skin/morph streams, animation bindings, runtime synchronization, and atomic rollback. Artist-authored imported meshes can also be assigned as exact LOD0/lower-detail groups through the Model Inspector or exact-leased MCP; editor and CLI artifacts serialize the same Babylon runtime links. Production bone/morph-aware reduction quality controls remain broader parity work.
- **Web/Desktop model importer overrides:** Model assets now persist closed, independently enabled Web and Desktop/Editor override profiles over Default scale/unit conversion, material/texture/animation inclusion, animation type, Optimize Game Object, colliders, compression, mesh optimization/welding, normals/tangents, and up to eight generated LOD levels. The Model Inspector authors every supported field. Web build profiles resolve Web settings, Electron profiles resolve Desktop settings, standalone CLI packing accepts `--model-platform`, and both editor/CLI cache keys include the selected target. Portable result evidence records the target, whether an override applied, base settings, and effective settings. `get_model_platform_overrides` and `set_model_platform_overrides` expose complete exact-leased maps to Codex CLI and Claude CLI. Mobile/console-specific model profiles and additional embedded texture codecs remain incomplete.
- **Editable imported-model texture extraction:** After extracting materials, the Model Inspector can now extract their embedded PNG/JPEG payloads into a selected project `assets` folder, defaulting to the model's sibling `Textures` folder, and rewrite every affected editable `.material` reference to the new project texture path. Babylon `base64String`, `url`, and `name` payloads share one scanner. A bounded shared planner validates real image signatures, caps individual/total bytes and unique images, deduplicates identical bytes, preserves human filenames, reuses only byte-identical assets, and blocks conflicts. Exact confirmation-gated apply uses same-folder atomic moves, transactional material backups, complete rollback, and registry refresh. `inspect_model_texture_extraction` and `extract_model_textures` expose the same operation to Codex CLI and Claude CLI. Additional embedded codecs remain incomplete.
- **Editable imported-model material extraction:** The Model Inspector can now extract every uniquely named embedded material into a selected project `assets` folder, defaulting to the model's sibling `Materials` folder, and persist exact source-material remaps back to the model importer. One shared bounded planner sanitizes cross-platform filenames, removes volatile Babylon runtime IDs, hashes canonical material JSON, reuses only content-equivalent assets, reports every create/reuse/conflict decision, and never overwrites an existing file. The mutation is exact-fingerprint and confirmation gated, stages atomic writes, rolls back created assets and importer metadata on failure, refreshes the persistent asset registry, and leaves the model importer stale for explicit rebuild. `inspect_model_material_extraction` and `extract_model_materials` expose the same workflow to Codex CLI and Claude CLI. The subsequent texture-extraction workflow now handles embedded PNG/JPEG payloads; additional embedded codecs remain incomplete.
- **Unity-style model material search:** Model importers now persist Source Material, Base Texture Name, or Model + Material naming and None, Local Materials Folder, Recursive-Up, or Project-Wide search. One bounded shared planner applies case-sensitive-first matching, nearest-parent priority, source-name fallback for missing base textures, explicit-remap priority, and deterministic ambiguity evidence without guessing. The same exact-fingerprint workflow executes in Inspector artifacts, editor builds, and CLI builds; scoped material path/content changes and newly appearing matches invalidate artifacts and CLI caches. The Model Inspector displays searched counts and per-source match/ambiguity evidence. `get_model_material_search` and `set_model_material_search` expose the complete leased configuration to Codex CLI and Claude CLI.
- **Generated imported-model LODs:** Model importers now author up to eight strictly ordered retained-quality/distance levels for static, skinned, morph-target, and combined character meshes and execute real quadratic-error simplification from an isolated copy of the source geometry. Exact provenance reconstructs all vertex streams, bone binding, morph data, and morph animation bindings while preserving hierarchy transforms and direct/MultiMaterial assignments; invalid deformation data rolls the entire generation transaction back, and already-authored LOD meshes remain unchanged. Generated meshes, Babylon distance-switching links, skeleton/morph resources, and runtime influence synchronization survive exact Inspector artifacts, editor export, CLI packing, and a fresh runtime reload. The Model Inspector authors the complete table and displays per-source geometry/deformation evidence; `get_model_generated_lods` and `set_model_generated_lods` provide exact-fingerprint read/replace workflows to Codex CLI and Claude CLI. Web/Desktop levels can be overridden independently.
- **Imported-model material remapping:** Model importers now persist up to 128 exact source-material → contained project `.material` replacements. The shared processor discovers duplicate source material objects, mesh/submesh usage, and texture counts; replaces direct assignments and MultiMaterial slots; records resolved/unresolved evidence; and executes identically in live editor import, atomic Inspector artifacts, editor export, and CLI packing. Replacement material assets are portable model dependencies, so content changes, missing files appearing, or transitive indexed texture changes invalidate exact importer leases and cached builds. The Model Inspector authors the table from discovered source names, displays resolution evidence, and extracts embedded materials plus PNG/JPEG textures into collision-safe editable project assets. Focused remap/search/extraction MCP tools expose the same paths to Codex CLI and Claude CLI. Additional embedded codecs and Unity material-file compatibility remain incomplete.
- **Executed LDR Texture Importer:** PNG, JPEG, BMP, WebP, GIF, TIFF, and SVG texture importer settings now execute in the File Inspector, editor export, CLI pack, and generated runtime. The shared bounded pipeline applies EXIF orientation, aspect-safe maximum sizing, nearest/bilinear/bicubic/Lanczos resampling, input-alpha removal, deterministic PNG/JPEG/WebP encoding, two runtime quality mip variants, optional raw RGBA bitmap plus descriptor output, and effective sRGB/linear sampling (with Normal Map and Lightmap forcing linear). Exact source/settings SHA-256 fingerprints guard atomic preview artifacts; portable `.bjstexture.json` manifests redirect authored texture paths to processed outputs and preserve KTX2 selection. The Inspector previews the executed artifact and reports dimensions, channels, output format, mipmaps, sampling, and CPU-readability. `get_texture_importer_result` and confirmation-gated `apply_texture_importer` are strict closed-world tools shared by Codex CLI and Claude CLI. PSD/TGA import, HDR/EXR/cubemap processing, platform-specific importer overrides, rotated atlas packing, and dependency-triggered automatic reimport remain incomplete, so the broader Texture/Image and Asset Pipeline rows remain Partial.
- **Animator conditional Entry and child-machine-source transitions:** The base machine, independent layers, and every reusable subgraph now persist ordered conditional Entry routes ahead of a validated default Entry destination. Routes may target direct states or child sub-state machines; nested conditions compose deterministically into qualified leaf destinations. Parent transitions sourced from a child-machine node become eligible when an active child leaf reaches Exit, including further parent Exit propagation and conditional Entry routing on machine destinations. The same compiler drives the Animator panel, graph edges, Restart behavior, editor preview, exported runtime, debugger inspection, and Unity `%YAML` import of `m_EntryTransitions` plus `m_StateMachineTransitions`. The focused `set_animator_entry_transitions` tool atomically replaces bounded ordered routes for the base, an independent layer, or a reusable subgraph; create/set-controller/set-layer/set-subgraph schemas expose the same closed model to Codex CLI and Claude CLI. Automatic Unity clip/AvatarMask/MonoBehaviour binding remains incomplete.
- **Animator Blend Tree child motion modifiers:** Every recursively nested 1D, 2D, or Direct Blend Tree leaf can now independently author and execute Unity-style Time Scale, normalized Cycle Offset, and Mirror in base states, layers, reusable subgraphs, and synchronized Motion overrides. Stable recursive motion identities allow the same Animation Group to appear more than once with different phase, speed, mirror, and weight. Modified and duplicate leaves use non-serialized runtime clones; negative Time Scale reverses playback, Cycle Offset changes the normalized start phase, and mapped humanoid Mirror swaps left/right targets while reflecting transform curves without mutating the authored source. The Animator panel preserves modifiers through mode/nesting changes, Unity YAML imports `m_TimeScale`, `m_CycleOffset`, and `m_Mirror`, debugger evidence exposes each independent runtime motion, and all recursive MCP schemas publish the strict fields to Codex CLI and Claude CLI. Automatic clip/AvatarMask/MonoBehaviour binding remains incomplete.
- **Animator Direct Blend Trees:** Recursive Blend Trees can now use Unity-style Direct mode in base states, layers, reusable subgraphs, and synchronized Motion overrides. Every child maps a numeric Animator parameter directly to its non-negative motion weight; Normalize Blend Values optionally scales the active weights to sum to one, while disabled normalization preserves raw weights. The same evaluator drives editor preview, exported runtime, nested parent weighting, masks, synchronization, and debugger evidence. The Animator panel switches among 1D, 2D, and Direct modes, authors each child parameter and normalization, and initializes missing numeric parameters. Unity YAML imports `m_BlendType: 4`, `m_DirectBlendParameter`, `m_NormalizedBlendValues`, and child motion modifiers with exact nested Motion binding replacement. Existing strict recursive MCP schemas expose the complete model to Codex CLI and Claude CLI. Automatic clip/AvatarMask/MonoBehaviour binding remains incomplete.
- **Recursive nested Animator Blend Trees:** Animator states, additional layers, reusable subgraphs, and synchronized Motion overrides now persist and execute recursively nested 1D, 2D Cartesian, 2D Directional, 2D Freeform Directional, and Direct Blend Trees. One shared evaluator multiplies parent/child weights, preserves independent duplicate leaves and child playback modifiers, and drives preview, exported runtime, playback lifecycle, masking, synchronization, and debugger evidence. The Animator panel can nest, flatten, and edit every tree level; Unity YAML conversion preserves nested `BlendTree` motions and exact external clip bindings instead of reporting them as unsupported. Existing strict controller/layer/override MCP schemas now publish bounded recursive definitions usable by Codex CLI and Claude CLI. Automatic clip/AvatarMask/MonoBehaviour binding remains incomplete.
- **Animator synchronized-layer motion and behaviour overrides:** Every synchronized layer can persist a bounded qualified-source-state map that replaces the mapped state's Animation Group or 1D/2D Blend Tree, its ordered StateMachineBehaviour bindings, or both. Explicit empty behaviour lists suppress mapped callbacks. Editor preview and exported runtime use the overridden state for playback, shared normalized timing, additive/override blending, enter/update/exit lifecycle, IK Pass dispatch, and debugger clip/source evidence—even when multiple source states map to one target state. The Animator panel authors clip and behaviour overrides per compiled source state; `set_animator_synchronized_layer_overrides` atomically replaces both complete maps through a strict MCP schema shared by Codex CLI and Claude CLI. Unity YAML `m_Motions` entries import through the same exact external Motion binding plan as ordinary states, including nested qualified state paths. Unity `m_Behaviours` MonoBehaviour references remain explicit unsupported diagnostics until project-script binding import exists; transition history, breakpoints, and frame stepping also remain incomplete.
- **Animator state behaviours and IK Pass:** Animator states in the base machine, independent/synchronized layers, and reusable subgraphs can persist up to 16 ordered script bindings. Scripts attached to the controller target node receive typed `onAnimatorStateEnter`, `onAnimatorStateUpdate`, and `onAnimatorStateExit` callbacks with controller/layer/qualified-state, machine-path, subgraph, timing, delta, and interruption context in editor preview and exported games. The Base Layer and every additional layer can also enable IK Pass independently, invoking typed `onAnimatorIK` after animation sampling and before existing rig/IK observers in the same frame. Disabled bindings/passes remain authored without executing; callback errors are isolated from animation evaluation; the live debugger reports bounded lifecycle and per-layer IK calls, missing targets/scripts/callbacks, recent events, and errors. The Animator panel authors the target, bindings, and IK toggles; the built-in `animator-behaviour` template provides both contracts; `set_animator_state_behaviours` and `set_animator_layer_ik_pass` expose strict authoring to Codex CLI and Claude CLI; and Unity YAML `m_IKPass` imports for Base and additional layers. Unity YAML MonoBehaviour binding import, transition history, breakpoints, and frame stepping remain incomplete.
- **Executed audio importer:** MP3/OGG/WAV/FLAC/M4A importer settings now drive real preserve/transcode processing with bounded, shell-free FFmpeg/FFprobe execution. Sample-rate conversion, mono downmix, loudness normalization, quality mapping, exact-fingerprint preview artifacts, Inspector playback, editor/CLI export, portable runtime sidecars, static decoded loading, and streaming loading are implemented. Three shared MCP tools inspect the result, apply it under an exact lease, and open the same Inspector. This closes the previous “persisted settings only” audio-import gap; mixer sends/effects, reverb zones, spatial profiles, and audio profiling remain incomplete.
- **Executed video importer:** MP4/WebM/OGV/MOV importer settings now drive real preserve, MP4, or WebM processing with bounded, shell-free FFmpeg/FFprobe execution. Quality mapping, aspect-safe even-dimension limits, optional audio removal, exact-fingerprint preview artifacts, Inspector playback, editor/CLI export, portable redirect sidecars, and runtime VideoTexture redirect resolution are implemented. Two shared MCP tools inspect and apply the exact leased result; `open_asset_inspector` opens the same video preview. Timeline video tracks, render-target output, color-management controls, hardware-encoder selection, and platform codec matrices remain incomplete.
- **Executed font importer:** TTF/OTF/WOFF fonts now support dynamic, bitmap, scalar-SDF, and genuine multi-channel MSDF processing with ASCII, Latin-1, or bounded custom Unicode character sets. Exact-fingerprint project artifacts, power-of-two atlas pages, glyph metrics, kerning, missing-codepoint evidence, Inspector dynamic/atlas previews, editor/CLI export, portable runtime manifests, page resolution, and browser `FontFace` installation are implemented. WOFF2 remains dynamic-only; full TextMesh Pro-equivalent text components, atlas-population mutation, fallback chains, rich-text authoring, and editor-wide font assignment remain incomplete.
- **Executed material importer:** Babylon `.material`, Babylon Node Material, and Wavefront `.mtl` importer settings now execute during preview and every editor/CLI build, including non-optimized builds. Project texture references are normalized and validated; bounded embedded PNG/JPEG data is extracted into deterministic SHA-256 assets and repaired when cached output is incomplete; Node Material graphs are compiled with errors, warnings, graph statistics, and shader evidence. Exact-fingerprint atomic artifacts, a specialized Inspector, portable `.bjsmaterial.json` reports, and two shared MCP tools provide the same workflow. Broader Unity material parity remains partial because complete nested material variants, full inherited texture/property conflict handling, shader keyword/variant management, and platform-specific material conversion remain incomplete.
- **Executed animation importer and Animation Window:** Babylon AnimationGroup `.animation` assets and legacy `.animations` track sets execute real 1–240 FPS resampling, optional redundant-key reduction, loop-default application, bounded clip/track/key validation, and root-motion target checks. `.animator` and `.controller` assets receive bounded structural state/transition validation without falsely applying clip settings. Exact source/settings leases, atomic Inspector artifacts, editor/CLI build output, portable `.bjsanimation.json` reports, and shared MCP tools use the same processor. Model importers additionally provide per-model source-group slicing, boundary interpolation, zero-based rebasing, Loop Time/Loop Pose, target masks, and root-motion evidence. A standalone Animation Window now provides clip selection, multi-track Dope Sheet and component Curve views, box/multi-selection, playback/scrubbing, event markers, direct curve dragging, frame scaling, duplication, deletion, value offsets, and linear/stepped interpolation. Broader Animation/Animator parity remains partial because complete controller import interoperability, arbitrary Inspector-property recording, the full tangent-mode library, controller-integrated muscle tracing, transition history, breakpoints, and frame-step debugging remain incomplete.
- **Nested Animator sub-state machines and reusable subgraphs:** Controllers now own bounded reusable state-machine definitions that can be instantiated repeatedly in the base machine, independent layers, or other subgraphs. A shared compiler validates missing references, duplicate names, cycles, depth/count limits, Entry routing, scoped Any State behavior, internal Exit routing, and qualified leaf paths such as `Ground/Locomotion/Run`. The same compiled graph drives editor preview, exported runtime, live debugging, the Animator panel, and four strict MCP tools for definition/instance lifecycle and flattened graph inspection. Complete controller import, transition history, and breakpoint/frame-step debugging remain incomplete.
- **Animator additive and synchronized layers:** Weighted layers can use Override or Additive blending. Additive playback creates cached non-serialized AnimationGroup clones relative to a normalized reference-pose frame, leaving authored clips unchanged for save/export. A synchronized layer references the Base Layer or an earlier layer, inherits its compiled state changes, maps qualified source states to its own qualified states, and always stretches its clips to the shared normalized state time while preserving independent clips, masks, weight, and additive/override behavior. Unity-style Timing optionally blends the synchronized clip duration into the shared source duration by layer weight. The Animator panel authors blend mode, reference pose, sync source, Affects Timing, and state mapping; the debugger exposes additive/internal-clone and synchronization evidence. `set_animator_layer_blending` plus the expanded controller/layer schemas expose the complete workflow to Codex CLI and Claude CLI.
- **Unity Animator Controller YAML import:** `.controller`/`.animator` assets now convert bounded Unity multi-document YAML into portable editor controllers with typed parameters, layers, direct/nested machines, graph positions, default and conditional Entry/Any State/Exit routing, child-state-machine-source transitions, recursively nested 1D/2D/Direct Blend Trees, child Time Scale/Cycle Offset/Mirror modifiers, fixed/normalized transition timing, interruption fields, all six Unity condition modes including NotEqual, IK Pass settings, and synchronized per-state Motion overrides. Direct trees preserve child weight parameters and Normalize Blend Values. External Motion and AvatarMask references remain explicit exact binding requirements; the File Inspector maps ordinary and override Motion entries at every Blend Tree depth into the current scene, editor/CLI builds share the artifact, preview/export runtime share the persisted controller, and two strict exact-leased MCP tools inspect/import it. Remaining import depth includes synchronized Unity MonoBehaviour behaviour binding, automatic Unity clip/mask binding, and broader Unity-version fixtures.
- **Executed model importer:** GLB, glTF, Babylon, OBJ, and STL assets use one shared editor/CLI processor for unit conversion and scale, material/texture/animation inclusion, collision flags, vertex welding, index optimization, normals/tangents policy, bounded low/medium/high vertex quantization, explicit and Unity-style searched project-material remapping, editable embedded-material/PNG/JPEG-texture extraction, and bounded deformation-safe static/skinned/morph LOD generation. FBX, DAE, and 3DS pass through bounded Assimp WASM GLB2 conversion and then the same processor. Generated character LODs reconstruct original vertex streams, four/eight-influence skin buffers, skeleton bindings, morph deltas/attributes, morph animation tracks, and runtime influence synchronization from exact source-vertex provenance without modifying the source mesh. Generic/Humanoid rigs can execute Unity-style Optimize Game Object processing: skeleton-only Transform animation targets are retargeted to Babylon bones, unused linked Transform nodes are removed, retained proxies are flattened, non-skeleton attachment parents are preserved automatically, and requested full paths or unique bone names remain synchronized for scripts, sockets, and IK targets. Up to 64 named clips can now be generated atomically from imported source AnimationGroups using inclusive ranges, evaluated boundary keys, frame-zero rebasing, Loop Time/Loop Pose, exact target masks, and validated position/rotation-Y root-motion selection. Web and Desktop build targets independently override the performance/content settings and generated LOD table through target-aware editor/CLI cache keys and evidence. Exact source/settings/dependency leases, Model Inspector evidence, processed `.babylon` artifacts, portable `.bjsmodel.json` redirects, editor/CLI build parity, focused clip/material/search/extraction/LOD/platform MCP tools, and the existing inspect/apply MCP workflow cover the same result. Additional embedded texture codecs and mobile/console-specific model profiles remain incomplete.
- **Per-model animation clips:** The Model Inspector authors named output clips from imported AnimationGroups with source selectors, inclusive frame ranges, Loop Time, Loop Pose, exact target-name/id masks, root-motion node selection, position mode, and rotation-Y extraction. The shared editor/CLI processor validates all definitions before mutation, creates independent frame-zero clips with interpolated boundaries, preserves playback metadata, reports source/output/root-motion evidence, and disposes original groups only after complete success. Exact importer fingerprints guard `get_model_animation_clips` and `set_model_animation_clips`. Model loading now uses asset containers so Babylon AnimationGroups survive editor, headless test, and CLI processing.
- **Humanoid Muscles & Settings pose preview:** Mapped Humanoid roles now expose normalized -1…1 local XYZ muscle values derived from authored limits and captured rest rotations, with degree readback, effective-limit source, and violation evidence. The Skeleton Inspector previews selected muscles, captured Rest Pose, or enforced horizontal arm-chain T-pose; active previews reapply after animation evaluation, restore the exact starting rotations, never enter Avatar/clip metadata, and are stopped before scene serialization. `get_humanoid_muscle_pose`, `set_humanoid_pose_preview`, and `stop_humanoid_pose_preview` expose the same temporary workflow to Codex CLI and Claude CLI. Production retarget visualization, constraint-rig graphs, advanced IK, skin-weight painting, and a controller-integrated muscle debugger remain incomplete.
- **Humanoid retarget debugger:** A non-mutating analysis compares one source clip and Avatar against a target Avatar across all 55 canonical roles. It reports source/target mapping, Avatar validity, recognized/compatible/skipped tracks, unsupported or disabled property reasons, local rest-pose correction Euler/angle evidence, human-scale ratio, and root/scale options before baking. The Skeleton Inspector adds source/clip controls, compact role diagnostics, guarded bake, and temporary cyan source/magenta target skeleton overlays with optional local axes. `inspect_humanoid_retarget` and `set_humanoid_retarget_debug_visualization` expose the same workflow externally. A full Animator runtime debugger remains incomplete.
- **Ordered Animation Rig layers:** Skeletons now persist enabled, weighted, explicitly ordered post-animation rig layers. Multi-parent constraints blend up to eight TransformNode sources while preserving captured position/rotation offsets; twist constraints extract signed local twist around an authored axis and distribute it across up to sixteen bones from captured rest rotations. The same evaluator runs in editor preview and exported games. The Skeleton Inspector authors layer order/weight/lifecycle and every constraint type, while a draggable freeform canvas visualizes source/bone inputs, constraint nodes, driven outputs, dependency edges, validity, and deterministic auto-layout. Nine shared MCP tools cover layer/constraint lifecycle plus exact-leased graph inspection and layout.
- **Chain IK Constraint:** An ordered rig layer can solve a validated 2–64-bone ancestor chain toward a TransformNode target using bounded FABRIK iterations and centimeter tolerance. Reachable targets converge while distant targets extend to total chain length; layer/constraint and chain-rotation weights blend the solve, while an independent tip-rotation weight blends the target's world rotation. The Skeleton Inspector authors root/tip/target and solver settings, shows chain length/reachability/current error, and visualizes the chain's dependencies in the freeform graph. The strict rig constraint MCP lifecycle exposes the same type and evidence.
- **Multi-Position and Multi-Aim Constraints:** Ordered rig layers support up to eight weighted TransformNode sources for both constraint types. Multi-Position optionally captures per-source position offsets, blends in world space, and locks any XYZ channels. Multi-Aim optionally preserves the current rotation offset, maps a configurable local aim/up basis toward the blended source position, and stabilizes roll against a configurable world-up axis with a safe parallel-axis fallback. The Skeleton Inspector creates both types, edits offset/masks/axis presets, shows active-source plus position/angle error evidence, and exposes their weighted source connections in the freeform graph. The strict rig constraint MCP lifecycle exposes all sources and settings.
- **Full-Body IK:** An ordered rig layer can solve 1–8 unique descendant effectors sharing one root. A bounded iterative CCD solver rotates shared and branch joints toward independently weighted target positions, then optionally blends each target's world rotation onto its effector. Authoring validates ancestry, non-zero path segments, target nodes, unique effector bones, weights, 1–64 iterations, and centimeter tolerance. The Skeleton Inspector creates the solver, adds/removes selected effectors, edits per-effector position/rotation weights and solver settings, shows per-effector reachability/error plus reached/average/maximum summaries, and visualizes every root/target/effector connection. Strict rig MCP schemas expose the complete nested effector set.
- **Override, Damped, and Blend Transform Constraints:** Ordered rig layers now include captured-offset Override Transform, frame-rate-aware temporal Damped Transform, and two-source Blend Transform. Each constraint independently weights and masks world-position and world-rotation XYZ channels. Damped Transform persists smoothed position/rotation state per live scene constraint, while Blend Transform validates two distinct TransformNode sources and interpolates between two offset-aware sources. The Skeleton Inspector creates and edits all three types and shows live position/rotation errors. The strict shared rig MCP lifecycle exposes sources, offsets, weights, masks, damping, and blend values; the freeform graph shows their data flow.
- **Skin-weight authoring:** Skeleton-bound meshes now expose complete validation and named-bone editing over Babylon's main and extra skin buffers, supporting one to eight influences per vertex. Exact-fingerprint replacement, selected-vertex or local-space spherical replace/add/subtract/smooth painting, normalization, pruning, invalid-reference repair, influence limiting, fallback binding, and local-axis mirror copying with automatic or explicit Left/Right bone remapping are available. The Skeleton Inspector uses Mesh Modeling vertex selections and provides Undo/Redo-safe painting, optimization, and X-axis mirroring. Editor save/export injects the live extra buffers omitted by Babylon serialization before writing binary geometry, and changed-count topology edits are blocked unless matching weights are supplied. Five strict MCP tools expose the same workflow.

### Verified updates after the table

- **Material importer correction (#362):** Material importer settings are no longer passive metadata. `.material` and `.mtl` assets are processed even when build optimization is disabled; standard Babylon/PBR and Node Material texture objects share bounded project-path validation and deterministic embedded PNG/JPEG extraction, while MTL map directives are parsed without mistaking directive options for texture paths. Node Materials compile through a real NullEngine/Scene build and return compiler errors, disconnected-input warnings, block/texture/output counts, and compiled-shader evidence. Editor and CLI builds publish portable `.bjsmaterial.json` reports, include extracted textures in asset manifests on both fresh and cached builds, and regenerate missing generated files. Exact source/settings SHA-256 leases guard atomic preview artifacts.
