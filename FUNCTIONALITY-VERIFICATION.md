# Zvibe Editor functionality verification

This document is the authoritative verification ledger for the editor feature audit. It separates implementation, automated tests, real editor UI testing, and direct MCP live testing. A feature is not considered fully verified until all applicable columns pass against the same current build.

Status values: `Pending`, `Running`, `Passed`, `Failed`, `Blocked`, or `N/A`.

## Acceptance criteria

For each feature family:

1. The feature opens and exposes its primary controls in the real Electron editor.
2. A representative create/read/update/runtime-or-export/delete lifecycle succeeds through physical UI actions where the editor exposes those actions.
3. The corresponding MCP capability/read/write/runtime tools succeed against the open editor.
4. MCP mutations are read back through MCP and visibly observed in the editor or exported runtime.
5. Invalid input and stale/destructive protections fail safely without corrupting the project.
6. Cleanup restores the test fixture and leaves no unexpected renderer, script, or server errors.
7. Applicable automated tests, build, lint, manifest generation, and contract validation pass.
